  Feature extraction approach

  Per 30 s epoch, per channel (Fpz-Cz, Pz-Oz), sampling rate 100 Hz → 3000
  samples:

  1. Welch PSD — scipy.signal.welch, Hann window, nperseg = 4 s (400 samples),
  50 % overlap → 0.25 Hz resolution, ~14 averaged segments. 0.25 Hz cleanly
  resolves every band edge (0.5/4/8/12/16/30), so no bin straddles a boundary.
  2. Band powers — integrate PSD with scipy.integrate.simpson over each band
  rather than summing bins, so the result is independent of the frequency grid.
  3. Relative power — each band divided by total power over 0.5–30 Hz. Note the
  five bands tile 0.5–30 Hz contiguously, so the five relative powers sum to
  exactly 1 per channel: one linear dependency per channel. Harmless for
  regularised logistic regression and for trees, but I'll state it in the README
  rather than leave it implicit.
  4. Spectral entropy — Shannon entropy of the PSD normalised to a distribution
  over 0.5–30 Hz, divided by log(n_bins) → bounded [0, 1] and comparable across
  epochs.

  → 12 features = 2 channels × (5 bands + entropy). Feature names are carried
  alongside the matrix (fpz_cz_delta_rel, …) so the confusion matrix and any
  coefficient inspection stay interpretable.

  Two methodological points I'll bake in:
  - Scaling inside the Pipeline. StandardScaler is fitted per training fold
  only, never on the full matrix — otherwise held-out subjects leak into the
  fit.
  - Out-of-fold predictions. Metrics and both figures come from
  cross_val_predict under GroupKFold, so the confusion matrix and the hypnogram
  plot describe genuinely unseen subjects. Per-fold macro-F1/kappa reported as
  mean ± sd alongside the pooled numbers.

  Gradient boosting will be
  HistGradientBoostingClassifier(class_weight="balanced") (sklearn ≥ 1.4) — it's
  the only sklearn booster that takes class weights declaratively rather than
  via a sample_weight that breaks under cross_val_predict.

  Four things I'd flag as the load-bearing decisions:

  - Sleep-period crop matters more than the model. Without it, ~70 % of epochs
  are out-of-bed wake and macro F1 becomes a wake-detection score. --no-crop
  reproduces that if you want the contrast.
  - Scaler lives inside the Pipeline, fitted per training fold. Standardising
  the full matrix first would leak held-out subjects.
  - early_stopping=False on the booster is deliberate — sklearn's built-in early
  stop carves a random validation slice out of the training fold, putting
  adjacent epochs of one subject on both sides of that split.
  - The five relative powers per channel sum to exactly 1 (the bands tile 0.5–30
  Hz contiguously). One linear dependency per channel: harmless under L2 and
  for trees, but it means logistic coefficients are only interpretable relative
  to each other within a channel. Documented in the README rather than hidden.

  Group disjointness is checked at runtime in iter_group_splits, not just

  EMG signal. I'll include it for what it can give (REM atonia vs. wake tone)

  Feature set — 39 per epoch, 117 after context

  EEG × 2 channels (14 each = 28). Existing five relative band powers and
  spectral entropy stay first, in order, then: log absolute power (0.5–30 Hz),

  Rolling windows — one mechanism for edges and gaps

  7.5 min centred = exactly 15 epochs, weighted by
  scipy.signal.windows.triang(15) (what pandas win_type='triang' uses). 2 min
  trailing = exactly 4 epochs, uniform, offsets −3…0 inclusive of current.

  Computed per recording, inside the per-subject loop — never across the
  concatenated matrix, which would leak features across subject boundaries.

  Rather than roll over array position, I reconstruct the 30 s lattice from the
  epoch onsets (slot = (onset − onset₀)/30), fill missing slots with NaN, and

  actually exist, so truncated edges and mid-night gaps are handled by the same

  each recording get partial windows. That's ~1 % of epochs, all sitting in the
  wake margin.

  Normalisation — per recording, inside the subject loop

  near-constant column divided by a near-zero spread amplifies pure noise, which
  would hurt real data and break test_audit.py's rare-class test.

  transductive within a night — it assumes the whole recording is in hand, which
